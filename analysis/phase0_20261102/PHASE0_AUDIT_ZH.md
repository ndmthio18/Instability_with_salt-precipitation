| 数据范围 | VTU 数量分布 | 可以支持什么 |

每步 sigmatop 有表面节点算术平均浓度、标准差和节点数；部分版本还有 Fourier / 模态投影。**没有每步局部最高浓度，也没有守恒盐库存或面通量。** 至少 43/320 条已访问历史运行的表面平均值在记录内达到 0.1，证明这些运行的局部阈值至迟也已达到，但不能用平均值首次达阈的时刻替代局部最大值首次达阈。

14 条 101 帧记录也不等于 14 条成熟指状输运证据。以 case 36877 的 nx=60 为例，已有增长幅度约 3.915 倍，但这仍是微小初扰动的增长，且不是主协议 nx=28。不可将它当作已验证的有效输运标签。

清点脚本只读每个首末 VTU 的前 64 KiB，字段 `visible_array_names_in_first_64k` 不是完整变量列表：ASCII 数据可能让后续字段落在更后的位置。另对四个候选相关末帧完整解析，确认含 `pw, sw, moleFraction, rhoW, velocity`。未对所有 VTU 进行完整数值审计。

## 4. 源码发现：必须先修正诊断认识

审阅位置：`source_snapshot/model.hh` 的 `computeStorage/computeFlux`，以及 `source_snapshot/main.cc` 的边界、密度公式、VTK 和时间循环。

1. **模型守恒量是 phi Sw x，而不是 phi Sw rho_molar(x) x。** 对应盐通量为 q x - D_eff grad x。`molarRhoW()` 函数存在，但没有进入这两项。上一轮讨论中的一般摩尔库存公式不能直接拿来要求该模型严格闭合。诊断约定改用模型一致的归一化库存，并把真实质量解释单列。
2. **VTK velocity 不能直接用作 Darcy 通量。** 主求解残差对速度乘了 krw，而所审阅 `main.cc` 的输出路径计算 `-K(grad p-rho g)/mu`，没有 krw。初始场也在时间循环更新速度之前写出。即使事后补乘 krw，单元中心重构仍不同于离散面的上风输运，不足以证明收支守恒。
3. 顶部盐 Neumann 通量为零，侧面为零；底部压力和盐浓度为 Dirichlet。全域盐库存可因底部交换改变，不能要求全域库存恒定。上部控制体闭合则需精确处理穿过控制面的离散通量。
4. 当前循环按 TEnd 结束，未见以表面局部 x=0.1 自动终止的逻辑。请求终点、LSA 阈值时钟和二维实际阈值必须分开。
5. 源码是当前远端工作副本；历史 executable 哈希不完整。以上明确约束下一步开发，但不能凭当前源码反推所有旧二进制的具体行为。

## 5. 候选 B 的字段来源冲突

`frodo:hf1/runs/shard-019/0079--case-38852--native` 的当前 input 与 constitutive_audit 都声明参考密度 1006.024104 kg/m3。然而保存末帧中 rhoW 与 moleFraction 按节点比较：

- 相对 input 明确指定公式的最大绝对误差：**2.014781 kg/m3**。
- 相对旧默认公式（rho_water=1000、旧摩尔质量和系数）的最大误差：**5.91e-12 kg/m3**。
- 后续 WP1 同一案例的末帧与明确指定公式误差：**5.23e-12 kg/m3**。

这是现存 input/manifest 与旧场的明确冲突。可能涉及不同历史二进制或文件更新，**本审计不武断确定原因**。该旧场和其物理解释隔离，不用于新的守恒或模型一致性论证。其原检测记录仍保留，不擅自重标 Paper 1 数据。B 的首选可复用来源切换为 WP1 v2 同一案例；仍需后续建立完整可执行文件—输入—输出链。

只抽查四个场，因此不能断言其他 432 条都没有此问题。需按 campaign 扩展少量代表性场与 rho(x) 的一致性核对，再决定旧场的复用范围。
